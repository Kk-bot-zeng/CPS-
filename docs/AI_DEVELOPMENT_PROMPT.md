# 可直接发送给二次开发人员 AI 的提示词

将下面整段内容发送给对方使用的 AI，并把方括号中的内容替换为本次实际需求。

```text
你现在负责“雷鸟全渠道 CPS 经营管理系统”的二次开发。代码仓库为：
https://github.com/Kk-bot-zeng/CPS-.git

本次需求：
[在这里完整填写需要开发的功能、页面、数据口径和验收效果]

开始前必须执行：
1. 阅读 README.md、docs/DEVELOPMENT_HANDOFF.md、.env.example、package.json 和本次涉及模块源码。
2. 从最新 main 创建独立分支 feature/[功能英文名称]，不得直接修改 main。
3. 先复述需求、影响范围、数据口径、实施方案和验收标准；存在歧义时先列明，不得自行改变业务口径。
4. 检查当前工作区状态，保留现有修改，不得使用 git reset --hard 或覆盖他人代码。

开发约束：
- 使用当前 Next.js 16、React 19、TypeScript、PostgreSQL 和 Python/FastAPI 技术栈，非必要不升级框架。
- 保持 TV 与显示器、京东/抖音/天猫渠道及各部门数据相互隔离。
- 数据库变更必须新增可重复执行的增量 SQL，并提供执行顺序和回退方案；禁止删除或覆盖历史数据。
- 数据导入保持幂等，正确处理计划白名单、SKU映射、达人/团长ID匹配、退款排除、重复数据和异常记录。
- 页面修改需统一现有设计语言，并检查布局、交互、分页、加载状态、空状态、错误提示和性能，不得只修改截图指出的单一点。
- 禁止读取、提交或输出生产账号、密码、Cookie、Token、数据库备份、真实业务数据和 .env 文件。
- 未经明确授权，不得执行真实京东同步、B站私信、生产部署或生产数据库写入。
- 不得删除与需求无关的代码，不得为了通过测试伪造数据或隐藏错误。

完成后必须：
1. 执行 pnpm build、python monitor-dashboard/verify_package.py、git diff --check，并修复发现的问题。
2. 对受影响功能进行回归测试，包括登录、渠道/品类切换、日期筛选、数据导入、看板、导出、分页和预警中相关部分。
3. 提供修改摘要、文件清单、数据库迁移、环境变量变化、测试结果、已知风险及回退方法。
4. 提交到自己的 feature 分支并推送，然后创建 Pull Request；不要合并 main，也不要部署生产服务器。
5. 最终把分支名称、提交哈希和 Pull Request 地址发给项目负责人。

验收标准：
[填写可以客观核验的结果，例如字段、计算公式、页面位置、响应速度、样例输入与期望输出]
```

建议每次只提交一个清晰需求。如果需求包含多个互不相关的模块，应拆成多个分支和 Pull Request，便于审核和回退。
